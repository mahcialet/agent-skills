# 技術文書の内容保護

## 変更しない対象

明示的な許可がない限り、次を文章校正の対象にしない。

- コードブロック、インラインコード、コマンド、オプション
- パス、URL、環境変数、設定キーと設定値
- API、型、関数、クラス、フィールドなどの識別子
- UIラベル、エラーメッセージ、ログ文字列
- Markdownリンク先、アンカー、参照ラベル、表の構造
- バージョン、SHA、issue番号、単位を含む数値

周辺説明だけを直し、literalは完全一致で維持する。誤記に見えても、本文とは別の
修正候補として示す。

## 用語と検索可能性

定義済み用語を自然さのために類語へ変えない。日本語訳と英語名が検索やUI照合に
必要なら、初出で「日本語（EnglishName）」のように併記し、その後の用法を統一
する。既存プロジェクトの用語集があれば優先する。

## 手順

前提、操作、期待結果、失敗時の分岐を区別する。順序を変えると動作が変わる
可能性があるため、技術的依存を確認せず「結論先行」で並べ替えない。元文にない
コマンド、更新、再起動、ロールバックを追加しない。

## コードと説明の整合

説明がコードやUIと矛盾して見える場合も、文章側だけを合わせて事実を変えない。
矛盾を指摘し、どちらが正か確認を求める。サンプル出力やエラー文字列を読みやすく
整形して意味を変えない。
