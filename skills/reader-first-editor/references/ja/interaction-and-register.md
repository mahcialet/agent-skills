# 対話とレジスター

明快さだけでなく、誰が誰に何を求める文書かを保存する。敬語や婉曲さは冗長語
として一括削除せず、関係性・責任・感情への作用を見る。

## 主なプロファイル

| プロファイル | 留意点 |
|---|---|
| neutral technical | 直接でよいが、断定と推奨を分ける |
| internal collaborative | 依頼、背景、相手の裁量、返信要否を明確にする |
| external polite | 敬意を保ち、長い定型句が要件を隠す場合だけ整理する |
| customer support | 共感、状況説明、解決手順、期待値を混同しない |
| incident / apology | 事実、影響、責任、謝罪、対処、次報を勝手に補わない |
| policy / requirement | 義務、禁止、例外、適用主体を弱めない |
| review feedback | 問題、影響、提案を分け、人への評価にしない |

## 依頼と次の行動

依頼では、元文にある範囲で対象、行為、期限、返信要否を見つけやすくする。
「ご確認ください」が承認・意見・受領確認のどれを求めるか不明なら指摘する。
不足する期限や担当を創作しない。

## 敬語と距離

二重敬語や過剰な定型句を直す場合も、社外向けを社内口調へ、謝罪を事務的通知へ
変えない。読みやすさのために直接化すると拒絶・命令の強さが増す場合は、元の
距離を保つ別案を使う。

## レビューコメント

対象箇所と技術的影響を先に明示し、提案を事実や必須事項と混ぜない。「なぜこう
したのですか」のように責任追及にも読める表現は、意図が情報確認なら質問対象を
具体化する。ただし、明示された強い要求を勝手に任意の提案へ弱めない。
