# 日本語技法の入口

日本語では「各文に主語を書く」「長文を短文へ分ける」を既定解にしない。
主題の継続と切替え、文末まで遅延する述語・否定・モダリティ、連体修飾、
対人関係を含めて、読者が関係を復元する負荷を減らす。

## 読み分け

- 文書全体の主張・根拠・注意の配置:
  `information-structure.md`
- 述語遅延、長い連体修飾、接続助詞、名詞化、過剰分割:
  `sentence-structure.md`
- 主題の切替え、主語省略、指示語、照応:
  `topic-reference-ellipsis.md`
- 条件、例外、否定、必須・推奨・任意・可能性:
  `modality-and-scope.md`
- 敬語、依頼、謝罪、レビュー、責任と距離:
  `interaction-and-register.md`
- 文長・構文・文末・段落の均質さと情報ペーシング:
  `rhythm-and-pacing.md`
- 用語、UI、識別子、コマンド、日英混在:
  `technical-content.md`
- README、手順、PR、メール、FAQ、UI等の切替え:
  `genre-profiles.md`
- 構造決定後の表記統一または `jtf-only`:
  `jtf-alignment.md`

## 優先順位

1. 意味、条件、適用範囲、モダリティを保存する。
2. 主題、論理関係、情報階層を見える形にする。
3. 日本語固有の保持・探索・復元負荷を減らす。
4. ジャンルと関係性に合う直接性・丁寧さを保つ。
5. 表記を統一する。

一つの主要な談話機能を一文で扱うことは有効だが、短く密接に結び付いた条件・
理由・結果まで機械的に分けない。分割後に接続関係を読者へ推測させるなら、
分割は改善ではない。
