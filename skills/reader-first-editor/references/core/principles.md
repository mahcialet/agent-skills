# 共通原則

このSkillでは、次の原則を意味保存契約の後に適用する。原則同士が衝突する
場合も、事実・条件・適用範囲・モダリティ・対人距離の保存を優先する。

## 1. Relevant：必要性

読者の目的に必要な情報と補足を区別する。ただし、既定の `review` と
`revise-safe` では不要と思われる情報も削除しない。移動・折り畳み・削除の
候補は根拠と対象を示し、削除は明示的な許可を得る。

## 2. Findable：見つけやすさ

文書の目的、結論、条件、手順、注意、次の行動を、読者が必要になる位置で
見つけられるようにする。見出し、段落、表、箇条書きは情報の役割を表すため
に使い、見た目だけを整える目的で増やさない。

## 3. Understandable：初読理解

未解決の主語・修飾・条件・否定を長く保持させない。用語を一貫させ、指示語
の参照先と論理関係を近づける。短文化、能動態、結論先行を機械的に適用せず、
読者が復元しなければならない関係を減らす。

## 4. Usable：行動可能性

元文に存在する主体、行動、期限、提出物、判断基準、返信要否を見つけやすく
する。存在しない情報を補って「使いやすく」してはならない。不足は `[要確認]`
や `[TODO]` として明示する。

## 数値の扱い

文長、段落長、同じ文頭や文末の連続、接続語の頻度は、本文を再確認するため
のtripwireに限る。単独の閾値で合否を決めず、その箇所で読者が保持・探索・
推論する情報を本文から説明できる場合だけ指摘する。

## Plain LanguageとControlled Language

このSkillは人間の初読理解を支援するPlain Language編集を行う。語彙・構文を
規格で制限するControlled Languageへの適合は検証しない。安全・保守手順など
特定規格への適合が必要な文書では、規格を置き換えず、範囲外と伝える。
